# lifelog

Минималистичный личный веб-журнал дня: подъём, тренировка, энергия, отчёт, отбой.
Один бинарник, одна база SQLite. Заполняется с телефона и ПК — в браузере или как
Telegram Mini App; доступ можно ограничить своей сетью Tailscale или включить через Funnel.

- **Одна запись = одни сутки бодрствования** (от подъёма до отбоя), а не календарный день.
  Дата дня — локальная дата подъёма; отбой может быть уже следующей датой.
- **Сон** не хранится, а вычисляется: подъём этого дня − отбой предыдущего.
  Если отбой не отмечен или между ними больше 20 часов (пропущены дни) — сон неизвестен.
- Go + `net/http` + `html/template` + SQLite (`modernc.org/sqlite`, без CGO).
  Шаблоны и статика вшиты в бинарник через `embed`. Фронт — HTML, CSS и немного JS, без сборки.

## Страницы и эндпоинты

| | |
|---|---|
| `GET /` | «Сегодня»: «Встал сейчас» → форма дня с автосохранением → «Лёг сейчас» |
| `GET /history` | все дни, новые сверху; любой можно открыть и поправить |
| `GET /days/{id}` | редактирование дня (включая отбой), удаление |
| `GET /chart?d=30\|60\|90` | график сна: дни × время суток, полоса от отбоя до подъёма |
| `GET /data` | экспорт и импорт |
| `GET /export.csv` `/export.json` `/export.md` | экспорт, параметры `?from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД` (включительно), `&inline=1` — показать вместо скачивания |
| `POST /import` | импорт CSV (файл `file` или текст `csv`) |
| `POST /wake` | новый день с подъёмом «сейчас» |
| `POST /days/{id}/field` | автосохранение одного поля: `name`, `value` (`now` для времени) → JSON |
| `POST /days/{id}/bed` | отбой «сейчас» |
| `POST /auth/telegram` | вход из Telegram Mini App (`init_data`) |
| `GET /healthz` | проверка живости |

Во всех экспортах есть вычисленная длительность сна. Markdown удобно вставлять в чат
с ИИ — на странице «Данные» есть кнопка «Скопировать Markdown».

## Запуск локально

```bash
ALLOW_NO_AUTH=1 go run .
```

В PowerShell: `$env:ALLOW_NO_AUTH = "1"; go run .`. Эта настройка нужна только для
локальной разработки. Для обычного запуска настройте вход через Telegram или
задайте обе переменные Basic Auth.

Откроется на <http://127.0.0.1:8080>, база — `./lifelog.db`.

```bash
go test ./...
```

Тесты клиентских сценариев можно запустить отдельно: `node --test internal/web/client_test.cjs`.

### Настройки (переменные окружения или env-файл)

Переменные можно задать в окружении или в env-файле (`KEY=VALUE`, `#` — комментарий):
его путь — `ENV_FILE`, у службы Windows — `C:\ProgramData\lifelog\lifelog.env`.
Окружение процесса важнее файла.

| Переменная | По умолчанию | |
|---|---|---|
| `ADDR` | `127.0.0.1:8080` | адрес. Оставляйте localhost — наружу через `tailscale serve` |
| `DB_PATH` | `lifelog.db`; у службы Windows — `%ProgramData%\lifelog\lifelog.db` | файл базы |
| `TZ` | часовой пояс системы | пояс для отображения и ввода, например `Europe/Moscow` |
| `BACKUP_DIR` | `<папка базы>/backups` | куда класть ежедневные копии |
| `BACKUP_KEEP` | `30` | сколько копий хранить |
| `BASIC_AUTH_USER`, `BASIC_AUTH_PASS` | — | если заданы обе — включается basic auth (не сочетать с Telegram) |
| `BOT_TOKEN` | — | токен бота от @BotFather; включает вход только через Telegram |
| `ALLOWED_USERS` | — | кому можно входить: Telegram ID и/или `@username` через запятую; владельца задаёт числовой ID, указанный первым |
| `WEBAPP_URL` | — | `https://…` адрес приложения; если задан вместе с `BOT_TOKEN`, запускается бот |
| `ALLOW_NO_AUTH` | — | `1` разрешает локальный запуск без аутентификации |

## Установка на Windows (служба)

Нужен Go 1.26+ и Tailscale. Запустите команды из папки репозитория в PowerShell **от имени администратора**.

```powershell
go build -o lifelog.exe .
.\lifelog.exe install
```

`install` делает следующее:

- копирует exe в `C:\Program Files\lifelog\`;
- создаёт службу `lifelog`: автозапуск при загрузке, перезапуск через 5 с после сбоя,
  запуск под виртуальной учётной записью `NT SERVICE\lifelog` (без пароля и без прав администратора);
- создаёт `C:\ProgramData\lifelog\` (база, `backups\`, `lifelog.log`, `lifelog.env`) с доступом только
  для администраторов, SYSTEM и самой службы;
- запускает службу.

Проверка: `curl.exe http://127.0.0.1:8080/healthz` → `ok`.

Настройки службы — в `C:\ProgramData\lifelog\lifelog.env`. Правка по SSH
(nano входит в Git for Windows), затем перезапуск:

```bash
ssh -t <пк> "\"C:\Program Files\Git\usr\bin\nano.exe\" C:/ProgramData/lifelog/lifelog.env"
ssh <пк> "powershell Restart-Service lifelog"
```

Или задайте переменные перед `install` — он запишет их в файл поверх прежних
(остальные строки не трогает; значение `-` закомментирует переменную):

```powershell
$env:TZ = "Europe/Moscow"
.\lifelog.exe install
```

**Обновление:** `git pull`, `go build -o lifelog.exe .`, `.\lifelog.exe install`
(служба остановится, exe заменится, служба запустится; данные не трогаются).

**Удаление:** `.\lifelog.exe uninstall` — удаляет службу, база остаётся.

Управление: `Get-Service lifelog`, `Restart-Service lifelog`, лог — `C:\ProgramData\lifelog\lifelog.log`.

> Если ПК уходит в сон, журнал недоступен. Для сервера отключите сон
> в «Параметры → Система → Питание».

## Доступ через Tailscale (HTTPS)

1. В админке Tailscale включите **MagicDNS** и **HTTPS Certificates** (DNS → HTTPS Certificates).
2. На машине с lifelog (на Windows — от администратора):

   ```bash
   tailscale serve --bg 8080
   ```

   Это проксирует `https://<машина>.<tailnet>.ts.net` → `http://127.0.0.1:8080` с сертификатом `*.ts.net`.
   С `--bg` настройка хранится в Tailscale и **переживает перезагрузку**.
   Проверить — `tailscale serve status`, выключить — `tailscale serve --https=443 off`.
3. По умолчанию приложение видно только устройствам вашего tailnet.

### Доступ без Tailscale (Funnel)

Чтобы открывать журнал с устройств вне tailnet (например, Telegram на чужом телефоне),
тот же адрес можно опубликовать в интернет через Tailscale Funnel — **только вместе с
входом через Telegram и PIN** (см. ниже). Укажите числовые Telegram ID в
`ALLOWED_USERS` и уберите `ALLOW_NO_AUTH` из настроек службы:

```bash
tailscale funnel --bg 8080          # включить (в первый раз Tailscale даст ссылку, чтобы разрешить Funnel)
tailscale funnel status
tailscale funnel --https=443 off    # выключить
```

После выключения снова включите доступ только для tailnet: `tailscale serve --bg 8080`.
С Funnel главный ключ — токен бота: при утечке перевыпустите его в @BotFather (`/revoke`).

### iPhone

Откройте `https://<машина>.<tailnet>.ts.net` в Safari (Tailscale на телефоне включён) →
«Поделиться» → «На экран „Домой“». Приложение откроется без панелей браузера, как обычное.

## Telegram Mini App

Журнал можно открывать кнопкой в Telegram-боте. Тогда вход — только через Telegram
и только для пользователей из `ALLOWED_USERS`; остальные видят
«You are not allowed to use this app» (и в боте, и в приложении).

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и возьмите токен.
2. Узнайте свой числовой Telegram ID. Для владельца нужен именно числовой ID.
3. Впишите в `lifelog.env` и перезапустите службу:

   ```
   BOT_TOKEN=<токен>
   ALLOWED_USERS=<Telegram ID владельца>,<Telegram ID второго пользователя>
   WEBAPP_URL=https://<машина>.<tailnet>.ts.net/
   ```

4. Напишите боту `/start` — придёт кнопка «Открыть журнал»; кнопка «Журнал»
   появится и в меню чата.

Бот работает через long polling (исходящие запросы к api.telegram.org), вебхук и
публичный адрес для бота не нужны. Для доступа к журналу через Serve включите
Tailscale на устройстве. Через Funnel журнал доступен и без Tailscale на устройстве.

### Как устроен вход

- При открытии мини-приложения JS отправляет свежую строку
  `Telegram.WebApp.initData` **целиком** на `POST /auth/telegram`, даже если сессия уже есть.
  Отметка во вкладке позволяет переходить между страницами без повторной отправки.
  Тот же Telegram ID сохраняет сессию и разблокировку. Смена аккаунта требует PIN заново.
- Сервер пересчитывает подпись HMAC-SHA256 (ключ — `HMAC("WebAppData", BOT_TOKEN)`)
  и сравнивает с `hash`, проверяет, что `auth_date` не старше 5 минут, и только потом
  берёт из неё ID и username. Для рассинхронизации часов допускается до пяти минут в будущем.
- Каждый `initData` принимается **один раз** (использованные `hash` хранятся в таблице
  `used_init_data`, переживают перезапуск). Скопированная ссылка мини-приложения
  (`…#tgWebAppData=…`) пригодна для первого входа до проверки сервером, поэтому
  такую ссылку нельзя передавать другим. Сервер берёт ID только из подписанных данных.
- Пользователь сверяется с `ALLOWED_USERS` (совпадение по id **или** username),
  затем ставится cookie сессии: подписана HMAC (ключ выводится из `BOT_TOKEN`),
  `HttpOnly`, `Secure`, живёт 30 дней.
- На **каждом** запросе пользователь снова проверяется по `ALLOWED_USERS`: убрали из
  списка и перезапустили службу — доступ пропал сразу, даже с живой cookie.
  Смена `BOT_TOKEN` обнуляет все сессии.
- После входа нужен **PIN** (ниже) — без него приложение и API закрыты.
- `http.CrossOriginProtection` отклоняет межсайтовые запросы на запись по браузерным
  заголовкам `Sec-Fetch-Site` и `Origin`. Клиенты без этих заголовков проходят обычную
  аутентификацию.
- Экспорт в Telegram скачивается через `Telegram.WebApp.downloadFile`: клиент
  качает файл без cookie, поэтому ссылка содержит подписанный токен на две минуты
  для конкретного формата и диапазона дат.

### PIN

Как экран блокировки iPhone: 6 цифр, клавиатура на экране. При первом входе
пользователь задаёт PIN, дальше вводит его после входа и после 10 минут бездействия;
кнопка «Заблокировать» внизу сразу отзывает разблокировки во всех сессиях пользователя.

- PIN хранится только как хэш PBKDF2-SHA256 (600 000 итераций, соль) в `users.pin_hash`.
- Для работы с журналом нужна cookie разблокировки. Она подписана, привязана к
  конкретной сессии и версии PIN и живёт 10 минут с последнего запроса. Ручная
  блокировка, смена и сброс PIN отзывают все прежние разблокировки.
  При обновлении со старого формата cookie откройте журнал заново из Telegram и введите PIN.
- 5 неверных попыток подряд — блокировка на 1 минуту, дальше 2, 4, 8 … минут (до часа).
  Во время блокировки не проходит даже верный PIN. Счётчик хранится в базе у пользователя,
  поэтому новая сессия, другой браузер или очистка cookies его не сбрасывают; попытка
  засчитывается до проверки — параллельные запросы лишних попыток не дают.
- Задать PIN можно, только пока он не задан. Сменить — «Данные» → «Сменить PIN»: нужен
  текущий PIN, неверный текущий засчитывается как неудачная попытка (та же блокировка),
  так что подобрать PIN через смену нельзя. Забытый PIN сбрасывается только на сервере
  (дальше пользователь задаст новый при входе):

  ```powershell
  & "C:\Program Files\lifelog\lifelog.exe" reset-pin <telegram id>
  ```

  Команда сама берёт базу службы (`C:\ProgramData\lifelog`), на Linux — `/var/lib/lifelog`.

### Несколько пользователей

Каждый день принадлежит пользователю (`days.user_id → users.id`), все запросы
ограничены текущим пользователем: тестер видит только свой журнал и не может открыть
чужой день даже по id. Чтобы дать кому-то попробовать — добавьте его id или
`@username` в `ALLOWED_USERS` и перезапустите службу; чтобы забрать доступ — уберите.
При Serve тестеру нужен доступ к вашему tailnet (Tailscale → Machines → Share).
При Funnel используйте числовые ID в allowlist: имя может смениться или перейти другому аккаунту.

`users.id = 1` — владелец: ему принадлежат дни, записанные до включения Telegram;
эту строку при первом входе получает аккаунт, чей числовой Telegram ID стоит
**первым** в `ALLOWED_USERS`. Запись по имени не может привязать историю владельца.
Локальный режим без входа и Basic Auth используют этого же пользователя.

При включённом Telegram в обычном браузере (в том числе PWA на iPhone) тоже будет
экран «You are not allowed to use this app» — вход только из Telegram.

## Бэкапы

Встроены в приложение: при старте и затем раз в час проверяется, есть ли копия за сегодня.
Если нет — делается `VACUUM INTO` в `BACKUP_DIR/lifelog-ГГГГ-ММ-ДД.db`, и остаются только
`BACKUP_KEEP` последних копий. Копия — обычная база SQLite: чтобы восстановиться,
остановите службу и положите копию на место `lifelog.db` (удалив `-wal`/`-shm`).
Разовая копия: `lifelog backup`. Каталог бэкапов должен поддерживать жёсткие ссылки
для атомарной публикации (например, NTFS или ext4).

База работает в режиме WAL.

## Импорт старых записей

CSV в формате экспорта, колонки по заголовку в любом порядке:
`date, wake_at, bed_at, train_start, train_minutes, train_type, energy, report`
(`sleep_minutes` игнорируется). Обязательна `wake_at`. Время — полное
(`2026-01-31T07:30:00+03:00`, `2026-01-31 07:30`) или `ЧЧ:ММ` при заполненной `date`
(`2026-01-31` или `31.01.2026`); отбой и начало тренировки раньше подъёма относятся к
следующим суткам. Если дни с такой датой подъёма уже есть, непустые ячейки обновляют самый ранний
из них. При равном времени выбирается меньший ID. Пробелы в отчёте сохраняются.
Разделитель — запятая или точка с запятой. Повторяющийся заголовок или лишнее поле
в строке считаются ошибкой. При любой ошибке не импортируется ничего.

```csv
date,wake_at,bed_at,train_minutes,train_type,energy,report
2026-01-30,07:30,23:45,40,бег,4,Обычный день
2026-01-31,08:10,00:30,,,3,"Лёг поздно, отчёт с запятой"
```

## Устройство

```
main.go                     конфиг, запуск, команды backup/reset-pin/install/uninstall
envfile.go                  env-файл настроек
platform_windows.go         служба Windows: SCM, установка, права на папку данных
platform_other.go           не-Windows: обычный процесс
internal/store/             SQLite, миграции, пользователи, Day, сон, текущий день, импорт, бэкапы
  migrations/NNNN_*.sql     версии схемы
  fields.go                 реестр редактируемых полей (разбор и проверка ввода)
internal/export/            CSV / JSON / Markdown и разбор CSV
internal/tg/                Telegram: проверка initData, allowlist, бот (long polling)
internal/web/               обработчики, вход, график (SVG на сервере), шаблоны, статика

```

«Текущий день» — самый поздний по подъёму день, если у него ещё нет отбоя. Старые дни
без отбоя (забыли нажать «Лёг») текущими не становятся; если текущий день открыт больше
20 часов, на главной появится подсказка и кнопка «Встал сейчас — новый день».

### Миграции

Файлы `internal/store/migrations/NNNN_описание.sql` вшиваются в бинарник. При старте
применяются по порядку номеров те, которых нет в таблице `schema_migrations`, каждая в своей
транзакции. Уже применённые файлы не меняйте — добавляйте новые.

- `0001_init.sql` — таблица `days`;
- `0002_users.sql` — таблица `users` и `days.user_id` (старые дни → `users.id = 1`);
- `0003_pin.sql` — PIN и счётчик неудачных попыток;
- `0004_used_init_data.sql` — использованные initData (защита от повтора ссылки входа);
- `0005_pin_version.sql` — версия PIN для отзыва разблокировок.

### Как добавить новое поле

Пример: «шаги за день».

1. Миграция `internal/store/migrations/0006_steps.sql`:
   ```sql
   ALTER TABLE days ADD COLUMN steps INTEGER;
   ```
2. `internal/store/day.go`: поле `Steps *int` в `Day`; колонку — в `dayCols`, `scanDay`,
   `insertDay`, `updateDay` (`user_id` подставляется автоматически).
3. `internal/store/fields.go`: запись в `Fields` с `Set` (разбор и проверка) и `Get`.
   Через реестр поле сразу заработает в автосохранении, сохранении формы и импорте.
4. `internal/web/templates/_dayform.html`: `<input name="steps" value="{{$v.steps}}">` в блоке `.field`.
5. По желанию: колонка в `internal/export` (`Columns`, `WriteCSV`, `jsonDay`, Markdown) и в истории.
6. `go test ./...`.
